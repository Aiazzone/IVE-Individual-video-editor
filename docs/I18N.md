# IVE — Internazionalizzazione

---

## 1. Scelta del sistema

**Traduzioni JSON con manager custom**, non Qt Linguist (`.ts`/`.qm`).

Motivi:
- gia' collaudato negli altri progetti (CLASSIFY_LABELING → AI_INSPECTOR);
- nessuna dipendenza da `lupdate`/`lrelease` nella build;
- cambio lingua **a runtime** senza riavvio;
- file JSON leggibili, diffabili e traducibili da chiunque senza tool Qt —
  requisito importante per un progetto open source che accetta contributi.

---

## 2. Struttura

```
ive/src/ive/i18n/
├── translation_manager.py     TranslationManager (singleton), tr()
├── translatable.py            mixin per widget/oggetti Python
└── locales/
    ├── en.json                SORGENTE — sempre completo
    ├── it.json
    ├── pt.json
    ├── es.json
    └── ...
```

Lingua di partenza: **inglese**. Lingue previste alla prima release:
EN, IT, PT, ES. Le altre si aggiungono con un solo file JSON, senza toccare
il codice.

## 3. Uso

### Python
```python
from ive.i18n import tr

label = tr("export.dialog.title")
msg   = tr("export.progress.frames", current=frame, total=total)
```

### QML
```qml
Text { text: qsTr("timeline.action.split") }
```

Il bridge `ui/theme_bridge.py` / `ui/bridge.py` installa un translator Qt che
risolve `qsTr()` attraverso lo stesso `TranslationManager`: **una sola fonte
di verita'** per Python e QML.

### Cambio lingua a runtime
```python
translation_manager.set_language("it")   # emette language_changed
```

- Lato QML: i binding si aggiornano se il testo e' un binding e la finestra
  chiama `engine.retranslate()` sul segnale.
- Lato Python: gli oggetti che espongono testo implementano `retranslate()` e
  si iscrivono a `language_changed`.
- **Regola:** costruire i widget senza testo e popolarli in `retranslate()`,
  chiamata anche dal costruttore. Cosi' non esiste testo che non si aggiorna.

## 4. Convenzione delle chiavi

Formato: `{area}.{contesto}.{nome}` — minuscole, `snake_case`.

| Chiave | Uso |
|---|---|
| `timeline.action.split` | titolo di un'Action |
| `timeline.action.split.desc` | descrizione (serve anche all'assistente NL) |
| `inspector.transform.scale` | etichetta di un parametro |
| `export.dialog.title` | titolo dialog |
| `error.media.unsupported_codec` | messaggio d'errore |
| `ai.subtitles.status.transcribing` | stato di un job |
| `menu.file.open_project` | voce di menu |

Aree previste: `app`, `menu`, `toolbar`, `timeline`, `preview`, `inspector`,
`media`, `effects`, `text`, `audio`, `ai`, `export`, `settings`, `plugins`,
`assistant`, `error`, `common`.

### Placeholder
Named, mai posizionali — l'ordine delle parole cambia da lingua a lingua:

```json
{ "export.progress.frames": "Exported {current} of {total} frames" }
```
```python
tr("export.progress.frames", current=12, total=300)
```

### Plurali
Chiavi separate con suffisso, selezione nel manager:
```json
{
  "media.selected_one":   "{count} clip selected",
  "media.selected_other": "{count} clips selected"
}
```

## 5. Fallback

`tr(key)` risolve in quest'ordine:
1. chiave nella lingua corrente
2. chiave in `en.json`
3. la chiave stessa, e un WARNING nel log (una sola volta per chiave)

Conseguenza: **`en.json` deve essere sempre completo**; gli altri file possono
essere parziali senza rompere nulla. Una traduzione incompleta e' accettabile,
una chiave mancante in `en.json` no.

---

## 6. Cosa tradurre

**Sì:**
- ogni testo visibile: label, bottoni, menu, tooltip, placeholder, titoli
- messaggi d'errore e di stato mostrati all'utente
- titoli e descrizioni delle **Action** (servono anche all'assistente NL, che
  deve capire le richieste nella lingua dell'utente)
- nomi ed etichette dei parametri degli effetti
- nomi dei preset di export
- testo dell'onboarding e degli stati vuoti

**No:**
- log applicativi (`logging.*`) → restano in inglese, servono al supporto
- chiavi e valori dei file di settings
- Action **id** (`timeline.split_clip`) → identificatori stabili
- nomi di codec, contenitori, formati (`H.264`, `MP4`, `ProRes`)
- unita' tecniche in f-string pure (`"1920x1080"`, `"30 fps"`)
- nome del prodotto, nomi dei plugin di terze parti
- identificatori dei modelli AI

---

## 7. Action Registry e traduzioni

Ogni Action dichiara una chiave, non un testo:

```python
@action(
    id="timeline.split_clip",
    title_key="timeline.action.split",
    desc_key="timeline.action.split.desc",
    ...
)
```

Da qui derivano automaticamente: etichetta nel menu, tooltip del bottone,
voce della command palette, e la descrizione del tool passata all'assistente.
**Aggiungere un'Action senza chiavi di traduzione e' un bug.**

---

## 8. Manutenzione

- Uno script in `tests/` verifica che: (a) ogni chiave usata nel codice esista
  in `en.json`; (b) nessuna chiave in `en.json` sia orfana; (c) i placeholder
  di ogni traduzione corrispondano a quelli inglesi. Il fallimento e' un test
  rosso, non un warning.
- Alle traduzioni contribuiscono utenti esterni: i file JSON restano
  ordinati alfabeticamente per rendere i diff leggibili.
- La lingua selezionata si persiste nei settings
  (`app.language`, default `"system"` → si deduce dal locale di sistema con
  fallback a `en`).
